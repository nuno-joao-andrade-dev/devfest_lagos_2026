🦙 Setup Part 2 • Local LLM Engine

Installing Ollama & Pulling gemma4:e2b

Ollama runs local LLMs as an HTTP server on http://127.0.0.1:11434. We use Gemma 4 (gemma4:e2b) for fast local inference & native tool calling.

1️⃣ Install Ollama (ollama.com)

  • 🐧 Linux: curl -fsSL https://ollama.com/install.sh | sh
  • 🍎 macOS: brew install --cask ollama (or download `.dmg`)
  • 🪟 Windows: winget install Ollama.Ollama

2️⃣ Pull gemma4:e2b & Verify

  • Pull the model once—then the entire workshop runs 100% offline!
  • Run npm run verify to confirm Ollama & Genkit are connected.
Terminal — Install Ollama & Pull Gemma 4
# 1. Install Ollama on Linux (or via Homebrew/winget): curl -fsSL https://ollama.com/install.sh | sh # 2. Pull the local Gemma 4 E2B model (~1.6 GB): ollama pull gemma4:e2b # 3. Confirm the model is installed locally: ollama list # 4. Run the Workshop Pre-Flight Verifier: npm run verify

Configuring Genkit + Local gemma4:e2b

🔌 Why Genkit + Ollama?

  • Unified TypeScript SDK: Same ai.defineFlow, ai.defineTool, and ai.retrieve APIs for local or cloud models.
  • Critical Flag: Set supports: { tools: true } on gemma4:e2b so Genkit unlocks tool calling!
  • Local Vector Store: @genkit-ai/dev-local-vectorstore persists embeddings in __db_lagos_tourism.json.
Genkit SDK Flows • Tools • RAG
⇄
Ollama Local gemma4:e2b
⇄
Local Vector DB __db_lagos_tourism.json

export const GEMMA_MODEL = 'gemma4:e2b'; export const ai = genkit({ plugins: [ ollama({ serverAddress: 'http://127.0.0.1:11434', models: [{ name: GEMMA_MODEL, type: 'chat', // CRITICAL: Unlock native tool calling for gemma4:e2b supports: { tools: true }, }], }), devLocalVectorstore([{ indexName: 'lagos_tourism', embedder: gemmaEmbedder, }]), ], });

🎯 What Step 1 Demonstrates

  • Wraps ai.generate() inside an observable ai.defineFlow().

🛑 The Baseline Failure

🧠 The Core Architectural Shift

Static RAG (Step 2) vs. Agentic RAG (Step 4)

❌ Static RAG Pipeline (Hardcoded)

Every user message forces a vector search—even if the user just asks "What is the wind speed right now?" or says "Obrigado!"

Step 2 Pattern (Fixed Pre-Fetch)
// Runs blindly on EVERY turn: const docs = await ai.retrieve({ retriever: lagosRetriever, query }); const res = await ai.generate({ prompt: `Context: ${docs}\nUser: ${query}` });

✅ Agentic RAG Pipeline (Autonomous)

Vector retrieval is a Tool (searchLagosKnowledge). gemma4:e2b reasons about intent and chains Vector Search + Live APIs on demand!

Step 4 Pattern (Autonomous Tool Selection)
// Gemma decides which tools to call & in what order: const res = await ai.generate({ model: gemmaModel, tools: [searchLagosKnowledge, getLagosWeatherAndMarine, findLagosTours], prompt: input.question, });
💡 Key Insight: The LLM’s description of a tool IS its prompt for when to use it!

Step 5: Taking Local Agents to Production

🛡️ 4 Production Upgrades in Step 5

  • 1. Multi-Turn Session Memory: Passes conversation history across turns so follow-up questions retain context.
  • 2. Deterministic Safety Guardrail: Cross-checks LLM output against the live marine sensor verdict (UNSAFE_CAVES_CLOSED can never be downgraded!).
  • 3. Execution Telemetry: Tracks latencyMs, toolCallCount, and exact tool inputs/outputs.
  • 4. Resilient Tool Loop: Supports both native Ollama tool calls & fallback JSON tool invocation.

const res = await generateWithToolsAndHistory({ systemPrompt: CAPITAO_GIL_PRODUCTION_PROMPT, history: input.history, // Multi-turn conversational state userMessage: input.message, tools: [ searchLagosKnowledge, getLagosWeatherAndMarine, findLagosTours, ], }); // Production Telemetry & Updated History return { answer: res.text, updatedHistory: res.updatedHistory, telemetry: { latencyMs, toolCallCount, model: GEMMA_MODEL }, };
